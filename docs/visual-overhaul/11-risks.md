# 11 風險與對策

[返回索引](README.md)

- **手機效能**：lightmap 與大量加法混色在低階 GPU 可能掉幀。對策：觸控裝置預設 MEDIUM、自動降級、LOW 為最終保底。
- **可讀性下降**：暗化與大量特效可能讓敵彈難以辨識。對策：敵彈與預警固定畫在 lightmap 與霧帶之後的可讀性層（圖層 11）。
- **render 寫入實體**：`entity.fx` 若被 sim 誤用會造成玩法依賴渲染。對策：在 `ARCHITECTURE.md` 明確規定 sim 不得讀 `fx`，並在 code review 時檢查。
- **事件佇列被濫用**：`fx-events` 若被拿來傳遞玩法資料會破壞模組邊界。對策：佇列只有 sim 寫、render 讀，內容只含視覺參數；呼叫點限定在 [06-combat-vfx.md](06-combat-vfx.md) 列出的 4 處。
- **換波卡頓**：地表快取重繪可能造成單幀停頓。對策：換波前預先繪製下一張快取並交叉淡入（[03-terrain.md](03-terrain.md)）。
- **改動面大**：render 幾乎全部重寫。對策：依 [09-phases.md](09-phases.md) 分階段，每階段可獨立運作並截圖比對，必要時可單獨回退某一階段。
- **截圖基準過期**：`output/playwright/` 舊截圖僅作為改造前對照，不再作為新版驗收依據。
